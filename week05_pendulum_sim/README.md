## 人机协同思考手记

### 一、意图设计思考

在编写初始 Prompt 时，我特意限制了「单文件、不依赖外部库」：目的是避免 CDN 网络加载失败的风险，确保浏览器双击即可跑通 MVP（最小可行产品），把「能不能运行」的不确定性降到最低。

### 二、报错自愈思考

点击重置按钮出现 ReferenceError 时，我把完整堆栈（报错名 + 文件行号）发给 AI。AI 的第一步不是改代码，而是「证据核对」：比对堆栈与当前源码后，发现报错中的内联 `onclick` 写法在现有文件中并不存在（全盘搜索亦无该符号），判定报错来自旧版本文件或浏览器旧缓存；随后从「IIFE 作用域 vs 内联事件全局作用域」的机制层面定位了根因——内联事件运行在全局作用域，找不到函数私有作用域里的函数；最后用无头浏览器自动化回归，验证当前版本 0 报错、重置功能正常。

**我的收获**：看报错先核对文件与行号，再谈修复；修复靠可复现的验证，而不是靠猜测。

### 三、人机协同哲学反思

AI 承担了约 90% 的 Canvas 语法与渲染细节编写，大幅压缩了「语法探索」的时间成本；而我作为人类主导了三件关键事：

1. **物理模型与参数的决策**：简谐振动 + 线性阻尼方程、L=200px / g=9.8 / 45° 等初始条件；
2. **UI 视觉标准**：深灰科技底色 `#1a1a24`、摆球光晕质感、拖尾与 HUD 的信息层级；
3. **最终达标验收**：拖参数看即时响应、调阻尼看自然衰减、点重置看复位、刷新页面看参数恢复——逐项检查后才算「完成」。

**结论**：AI 是高效的执行者，人是需求的提出者与结果的验收者。把「做什么、为什么做、做到什么程度算好」留在人手里，把「如何实现、如何排错」交给 AI，这是本次实验最大的协同心得。
